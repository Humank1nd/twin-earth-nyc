## 3. Anchor Verification Method — "Anchor Checker"

### 3.1 Procedure

1. **Position Camera:** Place the engine camera at the exact ENU coordinate of the anchor point, facing the direction specified in the photo reference description. Set camera FOV to 60 degrees (standard human-approximate perspective).

2. **Capture Screenshot:** Render a single frame at the anchor position. Output as lossless PNG at 1920x1080 resolution. File naming: `anchor-check_{ANC-ID}_{date}_{build}.png`.

3. **Load Reference Photo:** Retrieve the corresponding real-world reference photograph from the anchor reference library (`/assets/anchor-references/{ANC-ID}.jpg`).

4. **Overlay Alignment:** Composite engine screenshot and reference photo at 50% opacity. Identify at least 3 corresponding feature points (e.g., building corners, curb edges, sign positions) in both images.

5. **Measure Pixel Deviation:** For each corresponding feature point pair:
   - Measure pixel offset `(dx, dy)` between engine and reference.
   - Compute pixel distance: `d_px = sqrt(dx^2 + dy^2)`.

6. **Convert to World-Space Error:** Using the known camera FOV and distance to feature:
   ```
   d_world = d_px * (2 * distance_to_feature * tan(FOV/2)) / image_width_px
   ```
   Where `distance_to_feature` is estimated from the anchor's known geometry.

7. **Evaluate Pass/Fail:**
   - **Pass:** Maximum world-space error across all feature points < anchor tolerance.
   - **Warn:** Any feature point error > 50% of tolerance.
   - **Fail:** Any feature point error >= tolerance.

### 3.2 Automation

| Aspect | Specification |
|---|---|
| Trigger | Nightly CI build; on-demand after any truth-layer correction |
| Runtime | < 5 minutes for full 25-anchor sweep (headless rendering) |
| Output | JSON report: `{ anchor_id, max_error_m, mean_error_m, pass_fail, feature_points[] }` |
| Storage | Reports archived in `/qa/anchor-reports/` with build number and timestamp |
| Alert | Slack notification on any FAIL result; weekly summary digest for WARN results |

### 3.3 Reference Photo Standards

- All reference photos sourced from Google Street View (most recent capture), NYC DOT open data, or original site photography.
- Photos must include visible landmark features that correspond to modeled geometry.
- Each anchor must have at least one reference photo; high-traffic anchors (TKTS, One Times Square) should have 3+ angles.
- Reference photos are versioned alongside the anchor set document. Any update to a reference photo increments the anchor set minor version.
