## 1. Purpose

Times Square's visual identity is defined by its billboards. They are the single most GPU-expensive category of asset in the slice due to real-time video decoding, high-resolution render targets, and the light spill they cast onto surrounding geometry. This document inventories every billboard in the slice, defines the tiering rules that control when each billboard runs at full fidelity versus reduced states, establishes hard performance caps, and specifies the global light spill approximation that makes the billboard glow feel real without raytraced illumination.

## 3. Tiering Rules

Each billboard operates in one of four tiers at any given moment. The Show Director assigns tiers based on distance, frustum visibility, and available budget.

| Tier | Label | Condition | Content Rendered | Perf Cost | Draw Calls | Notes |
|------|-------|-----------|------------------|-----------|------------|-------|
| **T0** | Full Video | Distance < 30 m **AND** in camera frustum **AND** video budget allows (< 4 active) | Real-time video playback at 30 fps. Content decoded from video file or generated by procedural shader. Rendered to dedicated render target each frame. | **High** | 1 draw call + 1 video decode pass per billboard | Maximum fidelity. Only near-range billboards qualify. |
| **T1** | Low-FPS Loop | Distance 30--80 m **OR** video budget exceeded (5th+ nearest billboard) | Pre-cached keyframe animation. 5 frames per second. Keyframes extracted from source video at build time (or first play). Interpolation: nearest-neighbor (intentional digital-sign aesthetic). | **Medium** | 1 draw call per billboard. Cached frame swap every 200 ms. | Significant cost reduction. Still reads as "animated" from mid-distance. |
| **T2** | Static Emissive | Distance > 80 m **OR** explicitly culled from active budget | Single representative frame rendered as an emissive texture. No animation. Brightness responds to time-of-day (dimmer during daytime, full emissive at night). | **Low** | Standard material draw call. No special passes. | Minimal cost. Still contributes to the lit environment via light spill. |
| **T3** | Off | Not in camera frustum **OR** distance > 200 m | Nothing rendered. Render target released. No light spill contribution. | **Zero** | None | Fully inactive. Memory for render target reclaimed. |

### 3.1 Tier Assignment Logic

```python
def assign_billboard_tier(billboard, player_pos, frustum, active_video_count):
    dist = distance(player_pos, billboard.position)
    in_view = frustum.contains(billboard.bounds)

    if not in_view or dist > 200.0:
        return TIER_OFF

    if dist > 80.0:
        return TIER_STATIC_EMISSIVE

    if dist < 30.0 and active_video_count < MAX_VIDEO_SURFACES:
        return TIER_FULL_VIDEO

    # Between 30-80m, or within 30m but budget exceeded
    return TIER_LOW_FPS_LOOP
```

### 3.2 Priority Ordering

When multiple billboards compete for limited full-video slots (max 4), priority is resolved in this order:

1. **Hero billboards** (BB_H01--BB_H08) outrank background billboards (BB_B01--BB_B20), always.
2. **Nearest** billboard wins among same-class competitors.
3. **Largest** billboard wins among equidistant same-class competitors (XL > L > M > S > XS).
4. **Story-critical** billboards (flagged by mission system) receive a +1 priority boost, equivalent to being one distance tier closer.

## 4. Budget Caps

### 4.1 Hard Caps

These caps are **never exceeded**, regardless of artistic intent or gameplay state.

| Resource | Hard Cap | Enforcement |
|----------|----------|-------------|
| **Concurrent full-video surfaces** | **4** | 5th billboard attempting T0 is demoted to T1. No exceptions. |
| **Concurrent low-FPS loops** | **8** | 9th billboard attempting T1 is demoted to T2. |
| **Total billboard GPU time** | **2 ms per frame** | Measured via GPU timer query. If exceeded, action is taken (see 4.2). |
| **Total billboard video memory** | **64 MB** | Render targets + cached keyframes. If exceeded, lowest-priority T1 billboards release cached frames. |

### 4.2 Dynamic Resolution Scaling

If the GPU time consumed by all active billboards exceeds the 2 ms budget:

1. Identify the **lowest-priority active full-video billboard** (farthest hero, or any background).
2. **Reduce its render target resolution by 50%** (e.g., 1080p -> 540p, 512x512 -> 256x256).
3. If still over budget after reducing all possible targets, **demote the lowest-priority T0 billboard to T1**.
4. Repeat until under budget.

Resolution changes are applied with a 0.3 s cross-fade to avoid visible snap.

### 4.3 Emergency Mode

If the global frame rate drops below **35 FPS** for more than 0.5 seconds:

1. **All billboards demoted to T2 (Static Emissive).** No video decode, no animation.
2. **Light spill simplified** to a single ambient term per billboard (no per-frame color sampling).
3. Emergency mode persists until FPS recovers above **45 FPS** for 1.0 second (hysteresis prevents flicker).
4. Recovery is gradual: billboards restore one tier per 0.5 s, nearest first.

## 5. Global Light Spill Approximation

### 5.1 Concept

Every active billboard in Times Square emits colored light onto surrounding geometry -- facades, sidewalks, pedestrians, vehicles. This "light spill" is essential to the visual atmosphere, especially at night. True area-light simulation is too expensive for 28 billboards. Instead, the system uses a **point-light approximation** per active billboard.

### 5.2 Implementation

Each billboard in tier T0, T1, or T2 spawns a single dynamic point light with the following parameters:

| Parameter | Derivation | Update Rate |
|-----------|------------|-------------|
| **Position** | Center of billboard surface, offset 0.5 m outward (toward street) | Static (billboard doesn't move) |
| **Color** | Average color of the billboard's current displayed content. Sampled by downscaling the render target to 1x1 and reading the pixel value. | T0: every frame. T1: every keyframe change (5 fps). T2: once at load (static). |
| **Intensity** | `billboard_brightness * 0.3 * night_multiplier` | Every frame (brightness varies with content) |
| **Radius** | Proportional to billboard area: XL = 20 m, L = 15 m, M = 10 m, S = 7 m, XS = 4 m | Static |
| **Attenuation** | Inverse-square falloff, clamped to zero at radius edge | Standard light attenuation |

### 5.3 Night Multiplier

| Time of Day | Night Multiplier | Rationale |
|-------------|-----------------|-----------|
| Day (sun altitude > 20 deg) | 1.0 | Billboard light is subtle against bright ambient |
| Dusk/Dawn (sun altitude 0--20 deg) | 1.5 | Billboard light becomes more visible |
| Night (sun altitude < 0 deg) | 2.0 | Billboard light dominates the scene, full Times Square glow |
| Anomaly Event (override) | 2.5 | Heightened visual intensity during story events |

### 5.4 Light Budget

- **Max concurrent billboard point lights:** 12 (subset of 28 billboards; only those in T0, T1, or T2 and within 80 m of the player contribute light spill)
- **Shadow casting:** Billboard lights do **not** cast shadows (too expensive for 12 lights). Shadow-like effects are approximated by the ambient occlusion system.
- **Clustering:** If two or more billboard lights are within 3 m of each other, they are merged into a single light with averaged color and summed intensity (capped at max intensity).

### 5.5 Color Sampling Pipeline

```
For each active billboard (T0/T1/T2):
  1. Take current render target (or static texture for T2)
  2. Downsample to 4x4 (16 pixels)
  3. Compute weighted average:
     - Center 4 pixels: weight 2.0 (dominant content)
     - Edge 12 pixels: weight 1.0 (fringe content)
  4. Apply gamma correction (linear -> sRGB for light color)
  5. Clamp saturation to 0.8 (prevent over-saturated colored light)
  6. Assign to billboard's point light color
```

## 6. Billboard Content Library

### 6.1 Content Slots

Each billboard has a **content slot** that can be filled from the content library. Hero billboards have fixed, art-directed content. Background billboards draw from a shared pool.

| Content Type | Format | Duration | Count in Library |
|--------------|--------|----------|-----------------|
| **Video Ad Loop** | H.264, 1080p, 30fps | 15--30 s loop | 10 unique clips |
| **Animated Transition** | Sprite sheet, 512x512, 10fps | 5 s loop | 4 unique sequences |
| **Static Brand Image** | PNG, 1024x1024 | N/A (static) | 6 unique images |
| **Procedural Ticker** | Runtime-generated text scroll | Continuous | 1 system (parameterized) |
| **Event Poster** | PNG, 512x256 | N/A (static) | 8 unique posters (procedurally varied text) |

### 6.2 Content Rotation

Background billboards rotate their content assignment every **in-game hour** (real-time: varies by time scale). Rotation is deterministic based on a seed derived from `billboard_id + in_game_day`, ensuring consistency within a play session but variety across sessions.
